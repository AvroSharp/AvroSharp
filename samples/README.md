# Samples

Small console programs that show AvroSharp's main APIs end to end. Run one with `dotnet run --project samples/<name>`. CI runs each on every build, and each checks its own results, so they stay in step with the code.

| Sample | Shows |
|---|---|
| [GettingStarted](GettingStarted/Program.cs) | Parsing a schema, writing and reading a [`GenericRecord`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Generic.GenericRecord.html), reading data as a newer schema version, JSON ([`GenericDatumJsonWriter`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Generic.GenericDatumJsonWriter.html)), fingerprints ([`AvroSchema.Fingerprint64`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Schemas.AvroSchema.Fingerprint64.html)) |
| [ContainerFiles](ContainerFiles/Program.cs) | Writing and reading `.avro` files with the generic model: codecs and their sizes, header metadata, asynchronous reading, and reading as a newer schema. The code of [Container files](../docs/getting-started/containers.md) |
| [SchemaEvolution](SchemaEvolution/Program.cs) | Reading data written with one schema version as another: added and removed fields, promotions, aliases, enum defaults, nullable fields, and the pairs that fail. The code of [Schema evolution](../docs/getting-started/schema-evolution.md) |
| [LogicalTypes](LogicalTypes/Program.cs) | Dates, times, timestamps, decimals and UUIDs, as generated types and in the generic model, with precision and range checks. The code of [Logical types](../docs/getting-started/logical-types.md) |
| [Json](Json/Program.cs) | Avro's JSON encoding: how it differs from plain JSON, converting between binary and JSON, and reading JSON of an older schema. The code of [JSON](../docs/getting-started/json.md) |
| [GeneratedTypes](GeneratedTypes/Program.cs) | C# types generated from [a schema file](GeneratedTypes/Schemas/order.avsc) with logical types, a zstandard container file ([`AvroFileWriter`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Containers.AvroFileWriter.html), [`ZstandardCodec`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Codecs.ZstandardCodec.html)), reading every codec ([`AvroCodecs.All`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Codecs.AvroCodecs.All.html)), and reading a file an older schema version wrote |
| [GeneratorPackage](GeneratorPackage/README.md) | What an application writes to use the `AvroSharp.Generators` package: the project file, the MSBuild settings, schemas across files, and how to use the generator from source instead |
| [SerializableTypes](SerializableTypes/Program.cs) | Your own C# types with [`[AvroSerializable]`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Serialization.AvroSerializableAttribute.html): the schema the generator builds from them (camelCase field names, a nested record, an enum, a union of records), a container file, reading data an older version wrote, and lookup by type with [`AvroTypes`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Serialization.AvroTypes.html) |
| [Messaging](Messaging/Program.cs) | Single-object messages with a schema store ([`AvroMessage`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Messages.AvroMessage.html), [`AvroSchemaStore`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Messages.AvroSchemaStore.html)), Confluent schema-registry framing with an ID resolver ([`AvroRegistryMessage`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Messages.AvroRegistryMessage.html), [`IAvroSchemaIdResolver`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Messages.IAvroSchemaIdResolver.html)), and a stream of objects without a container ([`AvroStreamWriter`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Streams.AvroStreamWriter.html), [`AvroStreamReader`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Streams.AvroStreamReader.html)) |
| [Migration](Migration/Program.cs) | Apache.Avro code and the same with AvroSharp, each reading what the other wrote: schemas and fingerprints, the generic model, resolution, container files, generated types in the Apache.Avro compatibility mode, and exceptions ([`AvroSchemaException`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.AvroSchemaException.html), [`AvroDataException`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.AvroDataException.html)). It holds the code of [the migration guide](../docs/migrating-from-apache-avro.md) |
| [Confluent](Confluent/Program.cs) | Kafka with Confluent Schema Registry through [AvroSharp.Confluent](../docs/confluent.md): producing `[AvroSerializable]` orders, and consuming them as the same type, as generic values ([`AvroSharpGeneric`](https://avrosharp.github.io/AvroSharp/docs/api/AvroSharp.Confluent.AvroSharpGeneric.html)) and as a newer version of the type. It needs a broker and a registry: `docker compose up -d --wait` in its folder starts Redpanda ([compose.yaml](Confluent/compose.yaml)) |
| [KafkaFlowEvents](KafkaFlowEvents/Program.cs) | KafkaFlow with Confluent Schema Registry through [AvroSharp.KafkaFlow](../docs/kafkaflow.md): two `[AvroSerializable]` event types on one topic, each under its own subject (`TopicRecord`), produced with KafkaFlow's producer and handled by a typed handler per type. It uses the Confluent sample's Redpanda: `docker compose up -d --wait` in [Confluent](Confluent/compose.yaml) |

The samples use the source generator from this repository (`build/UseLocalGenerator.targets`), so CI tests the current code. An application references the `AvroSharp.Generators` package instead, as [GeneratorPackage](GeneratorPackage/README.md) shows; its project file reads like an application's, and `Directory.Build.targets` swaps the package for the source here.
